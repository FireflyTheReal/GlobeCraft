# v0.4.0 — Map data, places of interest and your own data

The changes since v0.3.0:

## Map data from GitHub

- **One map-data set**, built by GlobeCraft from the OpenFreeMap planet (OpenMapTiles
  schema) and published on this repository's `map-data` pre-release: borders, place
  names, roads, railways, ferries and airports, and places of interest, peaks, waters
  and parks. Tiles stream as you zoom, are cached on disk and fade in one by one,
  also while the view moves; a new border level cross-fades over the old one.
- **Place names to street level:** suburbs, quarters, neighbourhoods and localities
  join towns and villages below 40 km.
- **Roads** from motorways to residential streets, with **street names** written
  along their roads, upright and steady while the map moves.
- **Railways, ferries and airports**, runways and taxiways close up.
- **Line styles** for every kind of line (Settings → Map style): colour, width and
  dash, and label sizes.

## Places of interest

- **Symbols on round badges**, coloured by group (food, shopping, culture, health,
  transport, nature…), chosen from the OpenStreetMap kind of each place, so a
  bookshop shows a book and a marina a boat. **Peaks, parks and lakes** have badges
  too; seas and oceans keep their large names.
- Hover a place for its name and kind, or a peak for its height.

## Names that keep apart and stay put

- **All map names share one screen:** place names, street names, airports, places
  of interest and the names in your own data never overlap.
- **Zooming in no longer reshuffles names:** a name once drawn keeps its place and
  side and does not flash or fade in again when finer tiles arrive.

## Your own data (Add Data)

- **Add Data** (Layers ribbon, the Data pane or Command Search): a library of
  ready sources — seafloor (GEBCO, EMODnet), yesterday from space (NASA GIBS), tree
  cover loss (Global Forest Watch) and earthquakes of the past week (USGS) — plus
  forms for web maps (XYZ tiles, WMS with a layer picker) and features (GeoJSON,
  GPX, CSV by address or file).
- **Drop** GeoJSON, GPX and CSV files on the window.
- **My data** in the Layers pane: visibility, opacity, order, zoom to, and a
  **legend** — the layer's marker and line with counts, or a WMS service's own
  legend.
- **The Data pane:** favorites, recent sources, the library and your data;
  favorites export to and import from a file.
- The assistant can add and search sources (`data.add`, `data.search`).
- **Experience levels** (Settings → General): Basic, the default for new
  installations, leaves out the Earth models, other worlds and the web-service
  forms; Advanced shows everything. Settings from earlier versions open in Advanced.

## Globe and interface

- **What's here:** coordinates in every format, ground height, country, nearest
  place, local time and sun position for a point.
- The cursor shows the ground height everywhere, and picking follows the relief.
- Aircraft, ships and satellites move smoothly between reports.
- **Tile diagnostics** (Command Search) shows the imagery tiles in view by state,
  the download queues and rates.
- Windows and Linux use the system's own title bar and window buttons again.

## Fixes

- The Linux AppImage crashed at start on newer distributions (issue #1): it no
  longer bundles the Wayland and keyboard libraries, which must match the system's
  graphics drivers. On Linux the interface draws with Vulkan, and falls back to
  OpenGL when Vulkan is missing.
- Borders and names no longer flicker over 3D terrain; roads that double back no
  longer draw straight lines across the map; names no longer turn into broken
  glyphs after the font atlas refills.
- Linux packages now depend on the X11 libraries the window system loads at start.
- On macOS, quitting waits for a running screenshot, file save and cache writes.

## Known limits

- After a jump straight to street level, places of interest that load before the
  place names can keep a district or city name hidden; zooming in from further out
  shows them.
- The GPU globe renderer (a beta, on by default on Apple Silicon) is part of source
  builds with the `gpu` feature; release downloads use the CPU renderer.
- The macOS app is ad-hoc signed, not notarized: see the first-launch steps in the
  README.

## Verification

Formatting, Clippy (workspace, CPU-only and all features) and tests run in CI and
before every change. On an Apple Silicon Mac: the workspace tests, GPU parity with
the CPU (mean error 0; one channel two steps apart in the large-cache test), frame times (interface 0.19 ms;
tilted relief median 0.91 ms, p95 2.6 ms) and the map-data screenshots; the app was
used interactively. The release workflow builds every package; the Linux AppImage
is checked for bundled system libraries. Window smoke tests ran on Windows, Linux
(X11, KDE Wayland, Weston) and macOS. Windows, Linux and FreeBSD packages were not
used interactively.
