## Native window buttons

Windows and Linux use the operating system's own title bar again: native minimize,
maximize/restore and close, native drag and resize borders. The drawn buttons, the 6-point
resize edge (which also caught clicks meant for the panes) and their icons and locale keys
were removed. macOS keeps the merged header after the traffic lights; in fullscreen,
where macOS hides them, the header no longer reserves their width.

Checked by `.github/workflows/window-smoke.yml` (manual): Windows, Linux X11 (Xvfb +
Openbox), Linux Wayland (headless Weston) and macOS (the packaged `GlobeCraft.app`).
Each job maximizes, minimizes, restores and closes or quits the window through the OS,
uploads screenshots and a report, and runs the two benchmarks below.

## Review fixes

| Finding | Fix |
| --- | --- |
| Relief re-projection ran on every tile arrival | `TileCache::elevation_generation` bumps only for elevation tiles; the overlay ground uses it |
| Occlusion was tested for every vertex, on screen or not, 17 lookups each | Points are projected first and tested only near the view; samples higher than the highest relief skip the lookup. Benchmark (40,000 points, tilt 65°): 692,840 → 81,742 lookups, about 5–7× faster, identical on-screen answers |
| One batch failure blanked 24 tiles for 30 s; tiles appeared only when all were done | Tiles are fetched in batches of 8 (24 in flight); a failed batch retries after 4 s, a malformed tile after 30 s, and each batch shows as soon as it lands |
| macOS quit skipped cleanup | Before the macOS exit the app waits (bounded) for a running screenshot (20 s), a file save (5 s) and tile cache writes (2 s) |
| POI data was 11.7 GB | The map-data workflow keeps only the attributes GlobeCraft reads (`name`, `name_en`, `name:latin`, class fields, `rank`, `ele`, `ref`…); unnamed POIs are dropped. All sets were rebuilt; old parts are deleted by exact name |
