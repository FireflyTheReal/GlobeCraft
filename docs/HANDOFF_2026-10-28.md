# Handoff: review fixes, merged header and GlobeCraft name (2026-10-28)

This handoff records the code-review follow-up and the interface changes made in this
working tree. The project is the untracked `_rewrite/GlobeCraft` directory inside the
parent EarthCraft repository; none of these changes are committed.

## Result

- The separate title row is gone. The existing 38-point header now acts as the title
  bar on macOS, Windows and Linux.
- macOS keeps its native traffic lights and its native window behaviour.
- Windows and Linux use an undecorated window with drawn minimize, maximize/restore and
  close controls at the right of the header.
- The user-visible application name is **GlobeCraft**. The executable, crate, command
  and package file names remain `globecraft`.
- Review findings in the camera flight, frame crossfade, assistant notes, HTTP reads,
  traffic constants, dead reply state and documentation were fixed.

## Merged header

| Platform | Window presentation | Header and controls |
| --- | --- | --- |
| macOS | Full-size content view, transparent titlebar, title text hidden, native traffic-light buttons kept | Header starts after the native traffic lights. No custom window buttons are drawn. Dragging empty header space moves the window; double-clicking it maximizes/restores through the viewport command |

Details:

- `apps/globecraft/src/main.rs` sets the viewport flags above. The window title is always
  `WINDOW_TITLE = "GlobeCraft"`, so Mission Control, the taskbar and window lists still
  show the product name even though the title text is not drawn.
- `apps/globecraft/src/app/ui/window_chrome.rs` owns header dragging, the Windows/Linux
  controls and edge resizing. `apps/globecraft/src/app/ui/chrome.rs` reserves the traffic
  light width on macOS and the control width on Windows/Linux.
- macOS traffic-light width comes from `eframe::WindowChromeMetrics`, in AppKit points,
  and is divided by egui's zoom factor each frame. If the platform cannot report it, the
  app reserves 78 AppKit points.
- The old per-frame `window_title()`/`update_window_title()` formatting was removed. This
  avoids building and allocating a title string every frame and removes a source of title
  flicker.
- Window-control glyphs were added to `app/ui/icons.rs`; the four tooltips are in both
  Fluent catalogs.

### Name and packaging

- `CFBundleName` and `CFBundleDisplayName` are `GlobeCraft` in the generated macOS
  `Info.plist` (`scripts/package_tools.py`).
- The macOS bundle remains `GlobeCraft.app`; its executable remains
  `Contents/MacOS/globecraft`. `scripts/package_release.py` and the updater depend on that
  path, so it was deliberately not renamed.
- The Linux desktop entry, AppStream metadata, cargo-packager `productName` and Windows
  MSI product name were already `GlobeCraft`. Portable archives retain the `globecraft`
  executable name.

## Review fixes

### Correctness

- **`camera.flyTo` orientation:** flights now carry the requested heading and tilt in
  their destination (`Flight::with_orientation`) instead of mutating the camera before
  the flight starts. Ordinary flights keep the previous default destination orientation.
  Regression test: `requested_destination_orientation_is_reached`.
- **Compatible crossfades:** a frame is blended with the displayed frame only when both
  the camera basis and viewport rectangle match. This prevents blending frames from a
  differently sized viewport. Regression test:
  `crossfade_requires_the_same_camera_and_viewport_rect`.
- **Dead reply state:** the unused `Reply.failure` field and its initializers were
  removed. Failures already flow through `Result` and provider notes.

### Localization

- All 14 assistant note templates now map to Fluent IDs, including parameterized
  messages such as retries, provider declines, step limits and early stops. Both
  catalogs contain the same semantic IDs. The test formats every template with
  representative arguments and checks both languages for missing keys and leftover
  placeholders.

### Resource bounds

| Response | Limit |
| --- | --- |
| Cloud imagery | 32 MiB |
| Radar metadata | 1 MiB |
| Radar tile | 2 MiB |
| Search responses | 2 MiB |

The limits are named constants in `globecraft-data`; reads stop at the limit instead of
letting a misbehaving service grow the response in memory without bound.

### Maintenance

- Traffic-grid coordinates, ordering and sampling are unchanged; the former magic
  numbers became named constants in `crates/globecraft-data/src/traffic.rs`.
- Two `chunks_exact` uses with constant chunk sizes were replaced by `as_chunks` in
  `tiles/elevation.rs` and `benchmarks/replay.rs`, clearing the clippy findings without
  adding lint allowances.
- Documentation drift was corrected: `app/ui/chrome.rs` paths, `globecraft-core::orbit`,
  the interface description and the roadmap entry for the single header row.

- **The packaged macOS bundle has a narrow remaining gap.** It was built, signed,
  launched through LaunchServices, quit with Cmd+Q, dragged, double-clicked,
  zoomed and resized from its left edge. Finder and menu-bar labels were checked
  through bundle metadata and the running window owner, not visually in the menu bar.
- **Windows and Linux runtime behaviour is unverified.** The custom controls, drag,
  edge resizing, maximize/restore, high-DPI rendering and taskbar title need real
  desktop runs. The platform-gated code was not compiled by the macOS check because the
  Windows cross-build failed in a dependency before reaching it.
- **Wayland limitations are possible.** `ViewportCommand::StartDrag`,
  `ViewportCommand::BeginResize` and maximize requests depend on compositor support.
  X11 and Wayland (GNOME/KDE) should be tested separately, including whether the
  compositor adds its own decorations.
- **macOS display-name caveats.** The packaged bundle plist uses `GlobeCraft`; the
  menu-bar application name and Finder display name should still be confirmed from the
  packaged app. The fallback traffic-light inset (78 points) may need adjustment on
  unusual system font/scale settings. Native macOS border resizing and a very narrow
  window were not exercised in the smoke test.
- **No rendering performance benchmark was run.** The removed per-frame title
  formatting and the bounded reads are allocation/IO improvements; the network probe
  timings above are individual read measurements, not a frame-rate benchmark, and no
  percentage speedup is claimed.
- The changes are uncommitted and the `_rewrite/GlobeCraft` directory has no independent
  Git history inside the parent repository.

## Follow-up: header trim, live-layer flicker, relief and downloads

### Header

- The header's logo allocation and paint were removed; the File button now starts the
  row. The logo drawing stays in the icon set for the About command.
- The Quick Access Toolbar keeps Undo, Redo and Screenshot. Open KML and Save remain in
  the File menu and on the Home ribbon, so their duplicate header icons and width were
  removed (`QAT_COMMANDS`, `QAT_WIDTH` in `app/ui/chrome.rs`).
- The merged header, native macOS traffic lights, Windows/Linux controls and the
  **GlobeCraft** title are otherwise unchanged.

### Live-layer flicker

- `LiveInput::same_view` compares the camera, viewport, transport/POI layer toggles and
  whether each live layer has data, while ignoring the current tile snapshot pointers.
  Turning a layer off or clearing its data hides it at once; a new snapshot keeps the
  last geometry until the replacement is projected.
- `LiveOverlay::update` keeps the last prepared geometry for that view on screen while a
  newly arrived transport or places snapshot is projected, instead of returning `None`
  and blanking the layer. Motion steps keep their existing reuse.
- Regression tests: `a_new_tile_snapshot_keeps_the_last_geometry_until_it_is_projected`
  and the existing old-view/old-motion test in `apps/globecraft/src/app/live_geometry.rs`.

### Relief

- `LiveView` now carries the displayed relief setting, and `LivePreparer::with_elevation`
  builds terrain heights from the same elevation cache as borders and names.
- Roads, railways, ferries, runways/taxiways, airport markers, rivers, canals, park
  outlines and place/peak markers are projected through `overlays::ground_position`, so
  they follow the drawn relief. AIS vessels and satellite subpoints stay on the surface
  (water and orbit respectively).
- Regression test: `live_lines_are_raised_onto_the_relief`.

### Map-data downloads

- Archive opens are cached per URL with a `tokio::sync::OnceCell`; the cache map is locked
  only long enough to find the entry, so different parts open concurrently instead of
  serializing through one mutex across network I/O.
- A batch locates tiles in every part of a set concurrently (`Archive::locate`,
  `tile_parts_many`) and reads exactly contiguous byte ranges in one request per run
  (capped at 8 MiB). The first part to report a tile wins (band edges repeat the same
  bytes) and the remaining probes are cancelled once every tile has a home.
  `TileStream` downloads up to 24 tiles per batch.
- Pre-change probe: POI's 12 parts took about 4.2 s to open sequentially and roads' 13
  parts about 5.0 s; one POI view's 64 tile ranges merge into 10 exactly contiguous
  requests (transport: 61 into 8) with no extra bytes. After the change, the published
  POI batch probe read 144 tiles in 2.41 s with 16 requests and 4.8 MB (including the
  one-time archive opens). The coalescing is covered by
  `contiguous_tile_ranges_share_one_read`; the published POI batch probe is the ignored
  `a_places_view_batch_reads_its_tiles_together` test.

## Follow-up: terrain occlusion, hidden data and service bounds (2026-10-29)

### Terrain occlusion

- `globecraft-render::overlays::occlusion` adds `TerrainVisibility`. The CPU renderer
  has no depth buffer, so an overlay point is visible only when the straight line from
  the eye to it stays outside the relief. The line is sampled at
  `OCCLUSION_RAY_SAMPLES = 16` points, stopping one sample short of the target so its
  own elevation cannot hide it. The test reads the frame's loaded elevation cache,
  treats a missing tile as sea level and never requests tiles.
- It runs only while relief is drawn and `Basis::tilt_deg >=
  MIN_OCCLUSION_TILT_DEG = 1.0°`. The exact top-down default view does no elevation
  lookups. `Basis` now carries `tilt_deg`, set by `basis_from_ground`.
- Borders split into visible runs and resample across hidden or horizon stretches.
  Border labels, roads, railways, ferries, airports, rivers, canals, park outlines,
  POI lines and labels, vessels, placemarks and satellite subpoints are dropped where
  a ridge or island hides them. Vessels stay on the water surface but land can still
  hide them.
- Four unit tests in `occlusion.rs` and the model-preview
  `terrain_occlusion_drops_a_road_hidden_behind_a_ridge` cover the geometry and the
  integration. A tilted, relief-on view pays up to 16 elevation lookups per overlay
  point; no frame-time benchmark was run for this addition.

### Fields surfaced from the existing feeds

| Feed | Fields now shown on hover |
| --- | --- |
| Aircraft (OpenSky, ADSB.lol) | The raw `vertical_rate_fpm` is parsed from both providers; the tooltip reads climbing, descending or level (`0 ft/min`) as well as callsign, altitude, speed, heading and report age |
| AIS vessels | AIS vessel type, destination, draught, and length × beam, next to name, MMSI, position, course, speed and report age |
| Satellites (CelesTrak) | Orbital period, mean altitude and inclination from new `orbit::period_minutes` and `orbit::altitude_km` helpers |
| Airports | IATA and ICAO codes and the airport class (international, public, regional, military, private) |
| Places, waters and parks | Name and OpenMapTiles class |
| Peaks | Name and elevation in metres |

All new messages are in both `en.ftl` and `pt-BR.ftl`; the catalog consistency test
passes. A field the source did not send renders as `—`.

### Service bounds

- Boundary JSON and archive range requests now carry a 120 s whole-request timeout
  (`BOUNDARY_TOTAL_TIMEOUT`), so a body that trickles cannot outlive the connect/read
  limits.
- All boundary PMTiles range reads share one `tokio::sync::Semaphore` with six permits
  (`BOUNDARY_RANGE_CONCURRENCY`), because they come from the same release host.
- Each vector tile set's decoded cache is bounded by both its tile count and a 64 MiB
  estimated decoded-heap budget (`MAX_VECTOR_CACHE_BYTES`). It always keeps at least
  one tile, and the estimate excludes allocator overhead, so it is not a hard process
  memory ceiling. An eviction test covers the byte bound.
- These extend the earlier download work: per-URL archive opens, concurrent part
  probes, 24-tile batches and 8 MiB-capped contiguous range coalescing.

### macOS quit

- Before this change, Cmd+Q and the red close button closed the window and then aborted
  with `NSRangeException` from `_NSTouchBarFinderObservation` removing a KVO observer
  from `WinitView`; the same abort had also been seen with SIGTERM.
- `App::on_exit` now always finishes the settings writer and flushes the profiling log.
  Restart-save failures are still reported through the update notice; on a normal quit
  a failure is written to stderr. On macOS it then ends the process with code 0 before
  eframe tears the window down. A pending update restart execs the replacement from
  `on_exit`; a failed restart reports to stderr and exits instead of returning to the
  crashing teardown.
- The active-app restart handoff was simulated by setting the restart flag and closing
  the window. Before the fix it aborted with the same `NSRangeException` before `main`;
  after the fix the updated executable replaced the process, the app reopened and a
  subsequent Cmd+Q exited cleanly.
- Smoke test on the unbundled debug build: Cmd+Q and the red close button both exited
  with code 0 and no exception. A layer toggled immediately before Cmd+Q was present
  in `settings.json` after the process ended. SIGTERM on the packaged executable exited
  143 with no exception or crash report.
- This skips App destructors on a normal macOS quit: a background screenshot/KML job
  and best-effort tile writes can be cut short. Preferences and profiling data are
  flushed first.
